Purpose and interpretation
Use one distinct temporary service, DleOsQuotingIdentityProbe, running as NT SERVICE\DleOsQuotingIdentityProbe. It makes one Windows-authenticated request to an isolated HTTP.sys observer running as unelevated DLE-OS-HOST\Miguel. The observer permits only that exact virtual identity. It records authenticated name/SID/scheme, not credentials or authentication headers. Negative controls use Miguel's ordinary Windows identity and no credentials. Neither may receive 200.

This tests the same virtual-account class and loopback Windows-authentication mechanism, without occupying DleOsDevelopmentQuoting or port 5060. It does not certify the final service SID, final endpoint or application authorization. Microsoft documents that virtual accounts use computer credentials for network access; the exact same-host behavior is the observation needed here. Observed machine identity => reject and redesign service-specific transport/identity. A 401 or timeout without an observer identity is inconclusive about substitution, not proof of the expected name. Never grant the machine account broadly to make the test pass.

Why not avoid the URLACL?
Microsoft documents localhost HTTP >1024 development binding without administrator execution. Changing 127.0.0.1 to localhost changes authentication name behavior, so it would not faithfully qualify this path. An elevated observer is also possible in some configurations but increases process privilege. Neither alternative removes the need for a real SCM virtual-account caller. The recommended test keeps the numeric loopback target and a narrow temporary reservation; it is not an access-denial workaround.
